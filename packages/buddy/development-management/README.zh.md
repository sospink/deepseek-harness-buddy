# @sospink/dsh-buddy-development-management

[English](README.md) | 中文

## 概述

本 Host 包负责 Buddy“开发管理”。产品经理可创建、评审、指派和查看研发需求；研发类型匹配的区块链、算法、智能体应用开发工程师可接收已指派任务，并通过认证流式路由上传完整工程目录。任务状态、附件元数据、交付报告和审计历史会原子持久化到配置的私有根目录。

工程师提交已上传成果时必须填写成果说明。产品经理可以填写可选意见并通过，也可以填写必填原因后退回；被退回任务会重新开放上传和再次提交。只有验收通过后才能首次申请交付检查。提交与审核信息会作为任务数据和审计历史跨重启保留。

交付 Agent 会读取需求与配置的本地 Git 工作树，比较交付引用和目标引用，报告工作区与提交差异，把双侧都修改的文件标为疑似冲突，并记录每条配置检查命令的退出码、有界输出和耗时。它会生成 Merge Request 草稿，并给出“建议合并”或“暂缓合并”。干净报告只能进入“待人工确认”；产品经理必须显式确认，任务才能进入“已提交合并请求”。

## 安全与集成

- 仓库必须解析到任一 `repositoryRoots` 内；Git 接收参数数组，不执行拼接的 Shell 文本。
- 上传内容流式写入私有临时文件，在提交点重新校验，受单文件与单任务配额限制，并计算 SHA-256；包括 `.pt` 在内的大文件不会整体读入内存。
- 产品需求附件使用文档/原型白名单。研发任务允许完整仓库树，因为真实工程包含资源、Wrapper、Sidecar 和无扩展名文件。
- 配置 URL、项目和 Token 后，可通过 GitLab 真正创建、合并 Merge Request。未配置远程集成时，确认和合并必须提供真实 HTTP(S) MR/PR URL；服务不会伪造成功。

## 已知限制

- 暂未实现自动创建 GitHub Pull Request；GitHub 交付使用人工 URL 证据。
- 疑似冲突是保守的审查信号，不表示当前工作树已经由 Git 产生确认冲突。
- 当前版本同一任务路径的附件只追加不替换；替换与保留策略后续实现。
