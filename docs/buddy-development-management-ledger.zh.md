## 验收层级

- “平台实现”指可见入口、真实持久化或子进程/服务路径、Host 权限检查和可重复自动化覆盖均已存在。
- “真实外部集成”只有在配置目标 GitLab/GitHub 服务、项目、令牌和网络并实际走通后才完成。
- “已验收”指在客户交付环境执行全部适用动作、保留状态并完成截图取证。

## 2026-09-07 本机验收证据

- 浏览器完整走通任务 `#1 E2E 低空告警交付闭环`：产品经理创建/评审/指派，工程师接收并上传目录，真实比较 `feature/alert-delivery → main`，执行类型检查、测试和构建，生成 MR 草稿，经人工确认进入“已提交合并请求”，再进入“已合并”。
- 未配置远程集成且不提供 URL 时，确认提交被 `integration-not-configured` 拒绝；服务测试证明未提供合并证据时被 `merge-evidence-required` 拒绝。
- 整页刷新后，`#1` 仍显示“已合并”，目录树、交付检查结果、MR 内容和人工确认审计记录仍然存在。
- 任务文件按工程目录展示为可逐级折叠的目录树；文件保留上传角色、大小和下载入口；新上传会过滤 `.git`，历史遗留的 `.git` 附件也不会出现在树中。
- 开发管理 Host/Client 类型检查和定向 lint 通过；共 4 个测试文件、16 项测试通过，其中包含四类角色的 PNG/PDF/HTML、`.sol`、Python/`.pt`、前端/Java 文件矩阵；`build:lib:host` 与 `build:lib:client` 均通过。
- 客户内网 GitLab 的真实 MR 创建和合并仍依赖现场提供地址、项目和令牌；当前只完成 GitLab HTTP 契约测试与本机人工 URL 闭环，不能视为客户环境验收。
