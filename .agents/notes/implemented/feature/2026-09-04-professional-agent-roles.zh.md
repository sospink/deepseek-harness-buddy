# Agent Note：专业 Agent 身份

状态：已实现

[English](2026-09-04-professional-agent-roles.md) | 中文

## 问题

Buddy 的 Agent Preset 选择器回答一个会话使用哪些工具、权限和插件，但不能表达用户希望 Agent 采用哪种专业方法。产品调研、原型设计、软件架构、AI 工程、区块链工程和代码审查需要明显不同的工作方式。只显示标签会误导用户；不写日志的 Prompt 开关则会在刷新、恢复和派生时丢失。

## 决策

Buddy 增加产品自有的专业身份目录：通用 Agent、业务需求分析师、产品方案设计师、原型设计师、软件架构师、AI 应用工程师、区块链工程师和代码审查专家。空白会话 Hero 在“工作区”和“Agent Preset”旁放置分组身份选择器；“产品、技术、质量”分组便于浏览，简短说明解释每种身份改变的工作重点。

身份与 Preset 相互正交。Preset 继续负责工具、权限和插件组合；身份负责在动态模型上下文中加入稳定的专业工作方法。选择会追加完整值事件 `agent-role/selected`，`agentRole` Projection 用于冷启动会话列表和浏览器恢复。新会话会显式记录 `general`；没有身份事件的旧日志也折叠到同一默认值。

用户可以在工作区创建空白会话前暂存身份，当前空白会话可用后立即提交。Host 会拒绝未知身份，以及首个 `turn/start` 后的任何变更。这样可防止同一对话在中途静默改变专业规则，也能保持请求前缀稳定以利于 KV 缓存。Complete Persona Preset 继续保留屏蔽运行时上下文的既有权威，身份选择器不会削弱其安全契约。

## 考虑过的替代方案

**把每个身份都编码成 Agent Preset。** 未采用，因为这会产生组合爆炸和大量重复工具配置，也无法自然组成“标准模式 + 原型设计师”或“只读模式 + 代码审查专家”。

**只把选择保存在浏览器状态。** 未采用，因为模型无法可靠获得该身份，而且刷新、恢复或派生会话都会丢失专业身份。

**允许在活跃会话中更换。** 未采用，因为前序轮次由不同工作方法产生，回放和后续回答会出现内部不一致。

## 结果

每个普通专业会话会获得一段简短稳定的运行时上下文；通用 Agent 不增加 Token。身份可通过会话日志审计和回放。初始目录有意固定在产品代码中；自定义身份编写与设置管理界面留待后续实现。
