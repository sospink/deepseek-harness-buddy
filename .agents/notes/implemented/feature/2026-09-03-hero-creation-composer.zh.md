# Agent Note：首屏创作型输入舱

Status: implemented

[English](2026-09-03-hero-creation-composer.md) | 中文

## Problem

影片化欢迎页进入空白会话后，第一次真实交互需要在动态画布上保持视觉稳定。Hero 专用的超大浅色输入舱既与深色应用框架脱节，也形成了一套发送第一条消息后不会延续的 composer 外观。

## Decision

`hero` InputBar 变体复用原来的固定深色 composer 表面，并为新会话设置 132 像素静止高度、22 像素圆角、token 管理的材质、紧凑控件和蓝色圆形发送键。增加的纵向空间只用于全画布空白会话，已有对话仍保留原来的 94 像素底部输入框。它保留常驻的 Lexical 编辑器和现有的工作区、Agent 预设、指令、权限、计划、模型、上下文及提交控件。长草稿和附件仍可按功能需要扩展表面，但聚焦和失焦不会再切换紧凑与超大视觉形态。

工作区与 Agent 预设行保留克制的入场显示，而 composer 本身挂载时不再应用 Hero 专属的淡入、缩放、环境光、浅色材质或控件尺寸覆盖。真实的 adjudicating 与 submitting 输入状态仍会动画显示流动边框高光，并将发送箭头替换为缓慢旋转的加载器；不引入模拟计时器或平行草稿状态。`prefers-reduced-motion` 会移除加载与位移过渡。第一条提示与发送消息后的底部 composer 因而共享同一套视觉系统。

深色表面增加了一层不引入依赖的交互效果，其语言参考 React Bits 的 Border Glow、Spotlight Card 与 Glare Hover。鼠标移动时直接在 Card DOM 上写入两个 CSS 变量，用它们定位经过蒙版裁切的冰蓝色边缘追光，不进入 React state，也不改变输入框几何尺寸。聚焦只增强同一道光，不缩放或移动表面；Hero 新会话使用较明显的强度，已有会话的强度约为其一半。草稿首次让发送键可用时会播放一次短促高光，悬停则可再次触发克制的斜向扫光。已有的提交态流光边框和加载器拥有更高视觉优先级，减少动态效果模式只保留稳定的静态状态反馈。

新会话和已有会话的 composer 表面统一采用克制的近黑玻璃材质。多层半透明黑色与海军蓝渐变让后方表面仍能隐约透出，右上角冷色折射、内嵌顶部高光、底边沉降和深层柔和阴影共同表现亚克力厚度。原生背景模糊与饱和属于渐进增强，即使浏览器不支持滤镜，多层底色仍能保证可读性。聚焦只调整边缘亮度和阴影景深，因此 Hero 保持 132 像素、已有会话底栏保持 94 像素且不会位移；草稿状态也不再用旧的不透明底色覆盖玻璃。次级控件使用同一玻璃面内的低透明填充，不再显得像额外叠放的不透明小 Card。

欢迎页交接完成后，空白会话画布使用参考站原始且已本地打包的视频作为 WebGL2 ASCII 字符场的颜色与亮度来源。十像素字符网格、粗体等宽字符图集、视频原色输出、着色器流场常量、经过平滑的鼠标位移、60% 画布透明度、上下渐隐遮罩以及相对内容定位的中央暗区均与参考首屏一致，不再对其重新演绎。渲染设备像素比最高为 1.5，离开页面或可视区域时会暂停。WebGL2 不可用、用户选择减少动效或着色器初始化失败时，界面会保留视频回退，而不是显示空白工作区。

在这个空白会话阶段，会话列铺满整个框架，现有侧栏改为距框架边缘 12 像素的悬浮层。它默认以紧凑窄栏显示，避免覆盖居中的创作输入舱；用户在该空白会话中主动展开后，默认收缩不会被重复套用。它的真实展开、收缩和拖拽宽度仍由布局 store 提供。新的深蓝任务 Card 材质衔接影片化欢迎页与动态 ASCII 画布：Card 内部的近黑左下区域沿对角线过渡到右上角海军蓝，44 像素圆角外壳不绘制边框，仅由亚克力材质和深层阴影界定。底部功能入口保留在同一块连续亚克力平面上，仅用留白与会话浏览区分组；悬停反馈改为轻微的中性白雾，不再形成嵌套的蓝色 Card。标签、激活、按钮与导航 token 仅在该深色材质中局部调整。展开时，它会发布基于实时宽度的左侧避让空间，使输入舱在剩余可见区域内重新居中并限制宽度；收起后，输入舱平滑返回全画布中心，ASCII 背景始终保持全出血。工作区与 Agent 预设选择器合并在输入舱上方的紧凑半透明工具组中，统一几何尺寸、蓝色图标强调、克制的悬停与焦点反馈，并在现有菜单展开时旋转箭头。已有对话保留常规三列布局，并复用完全相同的内缩任务 Card 外壳。

## Alternatives considered

**重新设计所有 composer。** 被否：活跃会话需要紧凑的底部输入区以保留对话阅读空间，大型创作面只适合第一条消息之前。

**照搬参考页的附件、灵感、设计、线框和麦克风按钮。** 被否：无行为的复制品会暗示平台并不提供的功能，还会挤压真实的权限、计划、模型和发送控件。

**用欢迎页专用的模拟组件替换 composer。** 被否：重新挂载平行输入框会把草稿、编辑器、附件、指令菜单和无障碍状态与生产环境的 composer 拆开。

**为了背景平面加入 Three.js 和 React Three Fiber。** 被否：该效果只需要一个全屏三角形和两张纹理；直接使用 WebGL2 能保留参考效果的技术路径，同时避免在客户包中增加第二套渲染框架。

## Consequences

第一条提示现在使用应用原有的固定深色 composer 覆盖在影片化字符场上，底层仍是同一个真实功能 composer。该调整移除了只在首条消息前出现的浅色大输入舱及其聚焦光晕，不改变背景和工作区控件。背景限定在会话列内，该列在空白会话阶段会延展到悬浮侧栏后方；背景不接管指针事件，并在发送第一条消息后卸载，因此不会影响活跃对话和全画布原型。即使 GPU 渲染不可用，本地保存的原始 H.264 素材与视频回退也能让同一份源码交付包继续在受支持的 Windows 浏览器中使用。
