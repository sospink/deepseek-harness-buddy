# Agent Note: local Drive backup and restore

Status: proposed

[English](2026-08-30-local-drive-backup-restore.md) | 中文

## Problem

Buddy Drive 当前把元数据和源文件 Blob 持久化在同一 Host 上，但没有由 Provider 提供的可验证备份，也无法在 Host 更换后恢复。只复制 Drive 目录并不充分，因为元数据位于 Storage Domain，而 Blob 位于另一个 Provider 根目录。部分复制、变化中的 Blob、符号链接或过时的元数据文档都不能被当作可恢复资料库接受。

当前产品是单资料库本地部署，还没有企业身份、租户所有权、远程对象存储、加密密钥管理或外部备份 Scheduler。因此下一阶段采用本地、显式的维护能力，只作一个明确承诺：完整备份可以独立检查，并且可以原子恢复到另一个本地 Drive 根目录。

## Proposal

本地 Provider 写入带版本的备份目录，包含 `manifest.json`、`metadata.json` 和 `blobs/sha256/<prefix>/<digest>` 下被引用的内容寻址对象。Manifest 记录格式版本、资料库 ID、生成时间、精确的元数据摘要和字节数、每个唯一 Blob 的摘要和字节数以及聚合计数。元数据文件保留完整的 `buddy_drive` 状态，包括本地幂等审计字段；Manifest 摘要覆盖精确序列化字节。

创建备份时先校验内存状态和所有被引用的源 Blob，再写入目标旁边的私有临时目录，同步文件和目录，最后写 Manifest，并将临时目录原子重命名到此前不存在的目标。目标不能是 Drive 根目录或其子目录。生成的目录只允许 Owner 访问，生成的文件必须是普通非符号链接文件。

恢复时先完整校验源目录，然后才改变目标 Drive：目录项必须与 Manifest 一致，元数据和每个列出的 Blob 必须符合声明的摘要和字节数，元数据关系必须符合 Provider 配额，不能存在额外对象。非空目标默认拒绝恢复，只有调用方显式要求替换才允许继续。Blob 先发布，之后才提交元数据；提交会增加一条 `library/restore` 审计事件，并保留恢复得到的文件、版本和幂等记录。提交前任何失败都不会改变目标元数据；新发布但未被引用的对象由 Provider 已有的启动协调机制清理。

本阶段把留存定义为显式保留：在后续经过审查的留存策略确定前，所有不可变版本继续保存在备份和本地 Provider 中。不在这里加入自动硬删除、裁剪、加密、异地复制或浏览器任意路径控制。

## Alternatives considered

**只复制 Drive 根目录。** 否决：元数据文档属于 Storage Backend 根目录，因此只复制根目录无法恢复资料库关系或审计历史。

**无 Manifest 地复制 Storage Domain 文件和 Blob 树。** 否决：没有一个由摘要覆盖的声明来说明元数据与内容属于同一备份，过时或不完整的复制可能被误当成有效备份。

**先替换目标，再校验所有备份内容。** 否决：损坏或截断的备份可能在发现错误前破坏健康的本地资料库。

**在浏览器 UI 中使用任意路径提供备份和恢复。** 否决：浏览器输入不适合作为 Host 文件系统路径的授权；在有经过审查的运维入口前，维护路径仍是显式本地操作。

**现在加入自动版本裁剪。** 否决：目前没有提供留存期限、法律保留、恢复点目标或审批负责人，删除不可变版本会形成未经支持的数据丢失策略。

## Acceptance criteria

- 生成的备份包含带版本的 Manifest、精确的元数据摘要以及每个被引用唯一 Blob 的校验对象。
- 新的本地 Provider 可以验证并恢复备份，且文件、版本、审计和幂等关系保持完整。
- 缺失、损坏、修改、符号链接、路径穿越、版本不匹配和冗余备份项会在目标元数据改变前失败。
- 导出不会覆盖已有目标，也不会写入 Drive 根目录下。
- 恢复默认拒绝非空目标；显式替换只在完整校验完成后提交。
- 恢复失败时，目标原有元数据和可见内容保持不变。
- 本地 Provider 保留全部不可变版本，不声称加密、异地、企业或多租户备份。

## Risks

- 备份目录是本地维护产物，不是加密存储或异地灾难恢复系统。运维方必须保护备份目录和 Host 卷。
- 恢复过程中被其他进程修改的源目录超出单进程 Provider 权威范围；维护工具必须在源目录静止时运行。
- 显式替换后，如果提交之后的清理遇到意外文件系统项，旧的孤儿 Blob 可能暂时保留；启动协调仍是恢复责任方。
- 企业留存、加密、身份、租户隔离、调度和远程对象存储仍属于独立阶段，需要外部部署输入。
